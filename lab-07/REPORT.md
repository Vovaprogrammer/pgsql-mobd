# Лабораторная работа №7. Итоговый проект

Итоговый проект объединяет результаты ЛР 1–6 в законченную базу данных маркетплейса. Итоговая схема — в [`schema.sql`](schema.sql), скрипты и отчёты по отдельным темам — в папках работ.

## 1. Итоговая схема базы данных

Схема из ЛР 1 дополнялась в следующих работах, и новые объекты создавались скриптами этих работ вместе с демонстрационными запросами. Итоговая схема собрана в один DDL-скрипт [`schema.sql`](schema.sql) без демонстрационных запросов:

| Объекты | Работа |
|---|---|
| 16 таблиц с ограничениями `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`, `DEFAULT` и 9 индексов | ЛР 1 |
| представления `seller_revenue`, `product_rating` | ЛР 3 |
| таблица `product_price_history`, столбец `products.rating`, функции `place_order`, `seller_revenue_for_period`, триггеры `trg_log_price_change`, `trg_refresh_rating` | ЛР 5 |
| столбец `products.attributes`, индексы `idx_products_price`, `idx_orders_cancelled_user`, `idx_products_attributes` | ЛР 6 |

Столбцы `rating` и `attributes` объявлены сразу в `CREATE TABLE products`, а не добавляются `ALTER TABLE`. Скрипт удаляет перед созданием и `product_price_history`: при повторном запуске `schema.sql` ЛР 1 эта таблица оставалась со старыми строками и без внешнего ключа на `products`.

База собирается с нуля четырьмя скриптами, последние три выполняются в базе `marketplace`:

```
lab-01/create_database.sql   -- создание базы marketplace
lab-07/schema.sql            -- итоговая схема
lab-02/seed.sql              -- наполнение тестовыми данными
lab-06/jsonb.sql             -- заполнение products.attributes
```

Триггеры создаются до наполнения, поэтому `trg_refresh_rating` заполняет `products.rating` при вставке отзывов в `seed.sql`, и начальное заполнение рейтинга из ЛР 5 не нужно. Характеристики `attributes` — данные, а не схема, поэтому их заполняет `UPDATE` из `jsonb.sql`; `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` в нём пропускается, остальные команды только читают данные.

Схема собранной базы совпала со схемой после последовательного выполнения скриптов ЛР 1–6 (сравнение вывода `pg_dump --schema-only`). Данные отличаются только изменениями демонстрационных запросов ЛР 5: заказами 5001 и 5003, ценами товаров 2 и 5 и отзывом к товару 10. Повторный запуск сборки проходит без ошибок, скрипты ЛР 2–6 выполняются на собранной базе.

## 2. Дополнение словаря данных

Словарь данных по 16 таблицам ЛР 1 — в [`data_dictionary.md`](../lab-01/data_dictionary.md). Ниже — столбцы и таблица, добавленные в схему после ЛР 1.

### products: новые столбцы

| Столбец | Тип | Ограничения | Назначение |
|---|---|---|---|
| rating | NUMERIC(3,2) | — | средняя оценка товара, пересчитывается триггером `trg_refresh_rating` при добавлении отзыва (NULL — отзывов нет) |
| attributes | JSONB | — | характеристики товара, набор ключей зависит от категории |

Ключи `attributes` по корневым категориям:

| Категория | Ключи |
|---|---|
| Электроника | `brand`, `color` |
| Книги | `author`, `pages`, `cover` |
| Одежда | `color`, `material` |
| Дом и сад, Спорт и отдых | `color`, `warranty_months` |
| Красота и здоровье | `volume_ml` |

### product_price_history

| Столбец | Тип | Ограничения | Назначение |
|---|---|---|---|
| id | BIGINT | PK, IDENTITY | идентификатор записи журнала |
| product_id | BIGINT | NOT NULL, FK → products(id) ON DELETE CASCADE | товар, цена которого изменилась |
| old_price | NUMERIC(12,2) | NOT NULL | цена до изменения |
| new_price | NUMERIC(12,2) | NOT NULL | цена после изменения |
| changed_at | TIMESTAMPTZ | NOT NULL, DEFAULT now() | дата изменения; запись добавляет триггер `trg_log_price_change` |
